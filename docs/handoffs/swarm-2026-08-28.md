### Window size is NOT the thing the thresholds track — owner call, 2026-08-28

An earlier draft of this section argued the skill's 180k/250k thresholds were
"near-meaningless" because this session's cap is 1M rather than ~200k. **That is
wrong and the owner corrected it**, verbatim:

> *"the optimal window before dilution degrades performance is 100~150k, 200
> still ok but then the costs also start compounding, 300+k is just on both ends
> a bad deal. regardless of the context cap, even if it was 10M, the practical
> range is just few 100k at most."*

So the thresholds are about **dilution and compounding cost, not headroom**. A
1M cap does not buy permission to run to 500k. The skill's numbers are right as
written; percentage-of-cap is the wrong frame and should not be adopted.

**Consequence for drones, and it is the finding of this run:** a drone nearing
250k should be requesting retirement, and by 300k it should have handed off ~50k
earlier. `stat-memo` finished at 213k and `loot-round` at 191k — both inside the
band where cost compounds, neither flagged.
