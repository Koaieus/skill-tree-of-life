## Decisions taken (mine — overturn freely)

1. **#560 D7 relaxed: a snapshot MAY rebuild an entity the roster never named.**
   D7's premise ("the roster spawns exactly the named set") held only while both
   peers ran procgen. Procgen spawns ~112 blocker entities no roster names; a
   client that runs none would decode their nodes as unowned and the ownership
   fold would disagree immediately. `EntitySnapshot` now asks an optional
   `spawner` (`CommandLink.entity_spawner` → `GameRoot.spawn_snapshot_entity`,
   which refuses anything that is not a blocker). A **callback**, not an
   `instantiate()` inside the snapshot: a blocker's board is assigned per tier in
   code and `EntityStatBoard` refuses to mint a stat it has no field for, so a
   bare instantiate yields a blocker with no health.
   Row gains `scene_file_path` (interned) + `display_name`; `spawn_blocker` gains
   `preassigned_id`.
2. **Blockers spawn AFTER the roster** in `procgen_play_sandbox._setup_level`, so
   participant `entity_id`s are `1..N` on every peer by construction.
3. **The host PUSHES the world on join, as well as answering the client's pull.**
   They race and neither wins alone — see trap 2.
4. **The client's `_ready` awaits `command_link.resync_applied`** before arming
   VictorySystem / starting a turn / lifting the curtain. Unbounded on purpose;
   `SceneDirector`'s 30s reveal timeout is the backstop and `_reveal_ready`
   staying false is the honest report.
5. **START's broadcast + both roles' link release hang off `GameSession.run_started`**,
   not off the button — the seed is not resolved until the shell opens the run.
   `LobbyScreen` gained `remote_start`, `release_link()` (public) and a `_started`
   latch (see trap 3). `LobbyPanel` relays; `meta_root._on_remote_start` routes
   without re-opening the run.
6. **`Wire` binder exclusivity** (`claim_binder`/`release_binder`/`has_binder`);
   `EnetTransport._bind` returns bool and callers answer `ERR_ALREADY_IN_USE`.
   Refusal is a `push_warning` + return value, not `push_error` — GUT counts a
   push_error as an unexpected error and it matches `_adopt_live_link`'s shape.

## Two bugs found and fixed along the way

- **`GameRoot._focus_camera_on_player` read `player.position`** on an `Entity`,
  which extends `Node` and has none. Unreachable while every hero got a core;
  a joining client hits it every time. Now falls back to `Vector2.ZERO`.
- **`GraphSnapshot.restore_hp`, new, runs LAST in `CommandLink._on_resync`.**
  `node_health` is a POOL and `set_current` clamps to a cap derived from the
  OWNER's board — which `EntitySnapshot`'s pass 2 has not finished raising when
  `_decode_node` restores HP. Every owned node was silently clamped down and
  never raised again. Measured: 125 owned nodes losing 2-4 HP each, `own` and
  `topo` agreeing exactly while `accum` disagreed. Pre-existing; only bites once
  a peer stops generating its own (near-identical-cap) world.

## Traps a fresh agent must not re-discover

1. **`own`+`topo` agree, `accum` disagrees** ⇒ node HP, ⇒ pool clamping against a
   half-rebuilt owner board. Not a procgen desync. See `GraphSnapshot.restore_hp`.
2. **The client's `request_resync` races the host's 10s of procgen.** The host's
   level has not adopted the wire yet, `Wire` emits to nobody, the packet is
   dropped in silence and the client waits forever. Hence the host-side push in
   `GameRoot._on_peer_joined`.
3. **`GameSession.run_started` is a global autoload signal and `apply_received`
   re-emits it.** With two `LobbyScreen`s in one process (every headless test of
   this path) the host's handler re-enters from inside its own `send`, before its
   release can run — infinite recursion. `LobbyScreen._started` is latched BEFORE
   the send for exactly that.
4. Minor: a joined level in a unit test really dials, leaving an
   `ENetMultiplayerPeer` in the SceneTree-global `multiplayer_peer` slot and
   changing `get_unique_id()` for every later test. `Wire.stop()` in
   `before_each`/`after_each`.
