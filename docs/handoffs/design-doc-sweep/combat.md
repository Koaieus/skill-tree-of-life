## Notes

- **Node HP reset timing looks like a live contradiction, not just stale prose.** `docs/domain/node-hp.md` states the turn-start refill call was *removed* (with a "why" the survey didn't chase down), while this design doc's Node HP section (560–572, tagged LOCKED) and much of the surrounding design (dent-then-finish, focus-soak framing, Design Tensions #22) all depend on turn-start reset being real. This needs the owner (or a closer read of `docs/domain/node-hp.md`'s "Turn-start regen" section, which this survey didn't fully read) before deciding whether the design-doc section is IS, WAS, or simply wrong today.
- **`damage_floor` vs `min_damage_taken`**: the design doc uses `damage_floor` as the stat name throughout (Damage Pipeline, Entity-level defensive stats, Prototype Stat Defaults, Core Classes/Bulwark). The shipped stat is `min_damage_taken`; there is no `damage_floor` StatDef anywhere. Either a rename happened without a doc sweep, or `damage_floor` was always aspirational naming. Either way it's the single most-repeated stale name in the doc (4+ occurrences) and worth a global fix regardless of which sections move where.
- **Thorns section (618–620) directly contradicts this same file's own line 369.** Flagged above as WAS/false-today; whoever edits this doc should fix both at once rather than just moving one.
- **Core Classes summary (756–767) and Prototype Stat Defaults (771–790) both name unbuilt classes/stats as if current** — same pattern as `combat_system.md`'s already-fixed banner (line 3) but the body text wasn't brought in line with that fix.
- **Several UNSURE rows** (SP Reservation, Island Rule/Lifeline, two-layer health scope, Core-on-node shield, Loot Resolution STEAL/PROLIFERATE draft, targeting-primitives self-loop propagation, swing-profile presets) need a deeper code pass than this survey's budget allowed — grep alone can't confirm a multi-file mechanic's shape, only its stat/symbol existence.
- **`docs/domain/loot-system.md`** wasn't opened; CLAUDE.md's one-line summary ("killing-blow XP, tempo, and a relic on the victim's former core") suggests the shipped loot system is much thinner than the STEAL/PROLIFERATE/SKIP draft-pick system this doc describes (693–715) — likely all COULD, but confirm against that doc directly before cutting.
- **Cross-doc reference risk**: `core_classes.md`'s status table is cited here as authoritative for class-builtness (line 756, and the top banner line 3) — moving/deleting sections here doesn't break that reference since it points the other way, but any NEW domain doc created from this file's IS content should be linked from `core_classes.md`/`skill_node_addons.md` where they currently point into this file (e.g. Thorns→`skill_node_addons.md`, Melee Faces→same).
